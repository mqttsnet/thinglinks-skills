# 判据

所有工作流共用。本篇管**怎么判**,[answering-contract](answering-contract.md) 管**怎么说**。

## 空值的含义

| 现象 | 含义 |
| --- | --- |
| 属性取值为空 | 该时刻没有值,**不代表设备离线** —— 离线看连接状态 |
| 全部属性为空 | 从未成功上报,多半物模型或主题对不上 |
| 部分属性为空 | 设备没实现那几个属性,通常正常 |
| 统计条数为 0 | 这段时间没上报,不是「取值为 0」 |
| 时序表不存在 | 从来没上报过任何数据。比条数为 0 更严重,下一步也不同,见 [iot/never-reported](iot/never-reported.md) |
| 对比里某台条数为 0 | 常常正是「哪台不正常」的答案,不要当缺数据跳过 |

## 数值判断必须有量纲

拿实测值与物模型声明的单位、量程比。物模型未声明单位时,如实说明无法判断量纲,不要猜。

阈值远离实际取值区间(差一个数量级,或落在量程之外),通常是量纲不匹配导致的系统性误报。
但**越量程也可能是故意的**(用不可能的读数当告警开关),所以机械比对给出的是事实,不是结论。

## 极值与均值

- 判越限只看极值。均值抹平瞬时尖峰,据此得出的「没有越限」是反向结论
- 实测极值与物模型量程是两组不同的 min/max,判越限拿前者比后者

## 三组容易读反的返回

| 返回 | 正确读法 |
| --- | --- |
| 按人筛审计匹配不到人 | 是查无此人,该反问名字;不是「他没做过任何操作」 |
| 权限反查显式授权为空 | 管理员那批是通配权限,仍然能做;两批都要看 |
| 失败态 | 规则执行**没有**失败态(未执行=条件没命中);桥接**有**;OTA **有** |

## 搜索能力不一致

组织名、成员实名未加密,可以搜;设备名、分组名、用户名、昵称、联系方式是加密列,搜不了。
搜不了的字段不要当筛选条件传 —— 空结果会被读成「不存在」。

## 多源印证

单一信号不足以定性时用多源交叉:

| 源 | 回答 |
| --- | --- |
| 物模型量程与单位 | 这个值物理上可不可能 |
| 实际统计区间 | 这段时间实际在什么范围 |
| 同产品横向对比 | 别的设备同期什么样 |
| 连接状态与 OTA 时点 | 异常点附近发生过什么 |
| 规则触发统计 | 一次性还是系统性 |

三源同向可以定性;互相矛盾说明还没查清,继续查。展开见
[iot/anomaly-cross-check](iot/anomaly-cross-check.md)。
