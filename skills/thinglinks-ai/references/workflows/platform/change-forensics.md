# 谁改了什么

| 用户在问 | 用 |
| --- | --- |
| 这个配置是谁改的、昨天谁动了产品 | `get_operation_audit` |
| 我改过什么、这个是不是我动的 | `get_my_recent_operations` |
| 有没有异常登录 | `get_my_login_history` |

## 筛选方式

按人查传真实姓名,按动作查传描述,两者都是模糊匹配。

**匹配不到人是查无此人,不是这个人没动过。** 两者记录条数都是 0,但前者该反问名字是不是记错了。
返回里会给出关键字匹配到了哪几个人。

## 两个必须说清的边界

- **答不了「改成了什么值」** —— 只有操作元信息,没有请求参数与返回值
- **平台把查询也记进操作日志** —— 不带条件问「最近谁动过什么」会看到大量查询类操作;
  **结果里全是查询,说明这段时间没人改过东西**,这是结论不是「没查到」

## 数量口径

带截断标记时次数用总数,不要数返回的记录条数。

## 结论

给出:时间、操作人、动作描述、来源 IP;说明能查到的只到「谁在什么时候改过什么对象」这一层,
具体新值要到控制台的对应页面看。
