# 升级没到位排查

先分清用户问的是哪一个,两者常常不一致:

| 问题 | 用 |
| --- | --- |
| 任务里成功了多少台 | `list_ota_upgrade_tasks` |
| 设备实际停在哪个版本 | `get_product_version_distribution` |

**「升级到位了吗」看后者。** 升成功但版本没切、任务完成但设备没进范围,都会让两个数对不上。

## 逐台定位

`get_ota_upgrade_records` 拿到每台的结果,按这四种分,下一步完全不同:

| 现象 | 结论 | 下一步 |
| --- | --- | --- |
| 设备当前版本不在任务允许的来源版本里 | **没进范围**,不是失败 | 确认来源版本配置 |
| 指令下发状态显示没送到 | 多半设备离线 | `get_device` 看连接状态 |
| 设备回报了错误码 | 设备自己拒绝或失败 | 按错误码定位 |
| 进度长期停在同一个值 | 卡在下载或刷写 | 需要 APP 确认的任务没确认也会一直没动静 |

## 数值口径

- 成功率用 成功数 / 总数。**不要用 成功/(成功+失败)** —— 待升级与升级中的既不算成功也不算失败,排除掉会把成功率算高
- 总台数为空是没查到,不是 0 台
- 总台数用任务的计数,不要数截断后的逐台记录

## 版本分布的三种读法

- 没绑任何版本 ≠ 绑在旧版本
- 绑在已被清理的版本上要单独指出
- 产品版本号与升级包的 1.0.0 版本号不是一回事

## 结论

说清楚:目标版本是什么、实际到位多少台、没到位的分别卡在上面哪一类。
本服务不能发起升级、不能重试、不能上传升级包。
