# 身份与权限

## 选哪个

| 用户在问 | 用 |
| --- | --- |
| 我是谁、我在这个企业什么岗位、属于哪个部门 | `get_my_profile` |
| 我为什么登不上、上次什么时候登录、密码是不是过期了 | `get_my_account` |
| 我能不能做某件事、为什么看不到某个菜单、我是什么角色 | `get_my_permissions` |
| 谁能做某件事、谁是管理员 | `who_has_permission` |
| 我在哪个企业、企业什么时候到期 | `get_my_tenant` |
| 开通了哪些应用、某个应用什么时候到期 | `list_my_applications` |
| 我的权限配置有没有问题 | `audit_my_access` |

## 成对关系

`get_my_permissions` ↔ `who_has_permission`:一条答「我能做什么」,一条答「谁能做这件事」。
**方向选反了,答案也是反的** —— 用户问「谁能删产品」而你查了自己的权限,会得出「我不能删」这种
与提问无关的结论。

## 这个域特有的两件事

**权限反查的答案分两批,只看一批就是错的。** 被显式授权的人与租户管理员是两批;
管理员的权限码是通配的,不逐个资源授权。所以显式授权那批为空,不等于没人有这个权限。
两批分开也是有意的:「因为是管理员所以什么都能做」与「被单独授了这个权限」在权限治理上
是两件不同的事,合并之后两个问题都答不了。

**到期信息属于「出事才发现」那一类。** 企业到期后全体成员登录被拒;应用到期时间独立于企业,
可能先失效。用户问「为什么大家都登不上」时,`get_my_tenant` 往往比查账号更快命中。

## 与组织域的分工

「谁能做某事」拿到的是人名与岗位状态;要按部门找人、或要拿 `employeeId`,
去 [org](org.md)。
