# 时序与统计

## 选哪个

| 用户在问 | 用 |
| --- | --- |
| 这一小时怎么变的、有没有出现过尖峰 | `query_timeseries` |
| 这周平均多少、最高到过多少、上报了多少条 | `get_metric_stats` |
| 这几台里哪台不正常、谁最高、哪台没上报 | `compare_across_devices` |
| 现在是多少 | 回 [device](device.md) 用影子,便宜得多 |

## 不要自己算均值

时序返回的是窗口聚合:无数据的窗口会被跳过、各窗口点数不同,**「均值的均值」不等于真均值**,
而且会返回一个形状正确的数字,看不出错。

要均值就调统计工具;要自己算就取原始行(时序传原始模式,或影子带时间段)。

## 判越限看极值

窗口同时给 avg/min/max/last。只看 avg 会把瞬时尖峰抹平,得出「没有越限」的反向结论。

实测极值(设备真实上报的最大最小)与量程(物模型声明的范围)是两组不同的 min/max,不要混。

## 横向对比

- 只有同产品同绑定版本的设备在同一张时序表里、才可比,其余会被排除并附原因
- **被排除的设备必须在回答里说明** —— 少一台的对比读起来照样成立,但「谁最高」可能正好被它推翻
- 某台条数为 0 是「这台这段时间没上报」,常常正是答案

## 条数为 0 与表不存在

条数为 0 是这段时间没上报;报**时序表不存在**是这台设备从来没上报过,是一个结论不是查询失败,
接 [iot/never-reported](../../workflows/iot/never-reported.md),不要换时间窗重试。

同一台设备走横向对比却返回 `count: 0` —— 对比查的是超级表(存在),单台查的是子表(不存在)。
所以对比里的 `count: 0` 混着两种设备,要区分就单台查一次。
