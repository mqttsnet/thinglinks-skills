# OTA 与版本

## 选哪个

| 用户在问 | 用 |
| --- | --- |
| 有几个升级任务、升级成了吗、多少台成功 | `list_ota_upgrade_tasks` |
| 哪几台失败了、这台为什么没升上去 | `get_ota_upgrade_records` |
| 这个产品能升到哪些版本、最新版本是多少 | `list_ota_packages` |
| 设备都在什么版本、还有多少台没切过来 | `get_product_version_distribution` |

## 「升级到位了吗」看版本分布,不看任务

任务报的是「任务里成功了多少台」,版本分布报的是「设备实际停在哪个版本」。
**两者不一致是常态**:升成功但版本没切、任务完成但设备根本没进范围。
用户关心的「到位了吗」是后者。

没绑任何版本 ≠ 绑在旧版本;绑在已被清理的版本上要单独指出。
产品版本号与升级包那种 1.0.0 版本号不是一回事,别混着报。

## 成功率的算法

用 成功数 / 总数。**不要用 成功/(成功+失败)** —— 还在待升级和升级中的既不算成功也不算失败,
排除掉会把成功率算高,给出过于乐观的结论。总台数为空是没查到,不是 0 台。

## 「这台为什么没升上去」有四种答案

按这个顺序区分,它们的下一步完全不同:

1. **没进范围** —— 设备当前版本不在任务允许的来源版本里。这是最常见的,而且不是失败
2. **指令没送到** —— 多半是设备离线,接 [device](device.md) 看连接状态
3. **设备回报失败** —— 错误码才是设备自己给出的失败原因
4. **卡住** —— 进度长期停在同一个值,在下载或刷写阶段;需要人工确认的任务没确认也会一直没动静

只说「失败了」答不完,用户要的是下一步做什么。

## 只读

本服务不能发起升级、不能重试、不能上传升级包,也不返回升级包下载地址。

回答「能升到哪个版本」必须连启用状态一起看:非启用的包版本再高也升不上去,
只报版本号会给出一个做不到的建议。软件包与固件包是不同通道。
