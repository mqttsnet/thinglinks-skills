# 组织与成员

## 选哪个

| 用户在问 | 用 |
| --- | --- |
| 组织架构什么样、有哪些部门、每个部门多少人 | `list_org_tree` |
| 公司有哪些人、某部门有谁、某某还在职吗 | `list_employees` |

## 入口链

按组织找人是两步:`list_org_tree` 拿 `orgId` → 传给 `list_employees`。
直接问「研发部有谁」而跳过第一步,只能靠人名猜,拿不到准确范围。

## 这个域是搜索规则的例外

平台里大部分名称是加密列,搜不了 —— 设备名、分组名都是。
**组织名与成员实名不是**,所以这两个工具的按名搜索是真的能用的。

反过来,用户名、昵称、邮箱、手机号、身份证在平台里是加密的,既搜不了也不返回。
要联系某人,指向控制台,不要从别的工具里凑联系方式。

## 范围是整个企业,不是调用者所在部门

按组织的数据权限在 MCP 链路上不生效,看到的是本企业全部成员。
这件事影响的是**措辞**:不要说「按你的可见范围」,详见
[boundaries/data-visibility](../../boundaries/data-visibility.md)。
