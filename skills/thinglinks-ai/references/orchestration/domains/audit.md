# 审计与消息

## 选哪个

| 用户在问 | 用 |
| --- | --- |
| 这个配置是谁改的、昨天谁动了产品 | `get_operation_audit` |
| 我上周改了什么、这个是不是我动的 | `get_my_recent_operations` |
| 最近谁登过我的账号、有没有异常登录 | `get_my_login_history` |
| 我有什么未读消息、有没有待我处理的 | `get_my_notifications` |

## 成对关系

`get_my_recent_operations` ↔ `get_operation_audit`:一条答「我改过什么」,一条答「谁改过什么」。
事故复盘的第一问是后者。

## 这个域特有的三件事

**查不到人和这个人没做过,是两回事。** 按人筛时若匹配不到这个人,工具会明确告诉你是查无此人;
此时该反问名字是不是记错了,而不是回答「他没做过任何操作」。两者的记录条数都是 0,
但对用户的意义完全相反。

**平台把查询也记进操作日志。** 不带条件问「最近谁动过什么」,返回里多半是查询类操作。
**结果里全是查询,说明这段时间没人改过东西** —— 这是结论,不是「没查到」。

**答不了「改成了什么值」。** 操作日志只有元信息,没有请求参数与返回值(完整报文可能带口令
与他人数据)。被追问时说明这一点,不要从描述文字里猜。

## 通知答不了告警是否送达

站内信与告警记录之间没有可靠关联,平台发通知时没回填关联业务字段。
看到时间相近的通知也不能断定就是那条告警的 —— 详见
[boundaries/unanswerable](../../boundaries/unanswerable.md)。
