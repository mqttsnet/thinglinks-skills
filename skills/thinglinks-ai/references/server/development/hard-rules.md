# 硬规则

违反其中任何一条都会造成**静默错误** —— 编译通过、运行不报错、行为是错的。

## 1. 取数只走 `/inner/**`

不得调用对外 Web 接口。现成接口不是 inner 形态时,在下游新增 inner 接口再包装,不将就复用。

`/inner/**` 在网关拒绝清单内,只能服务间直连,不会因为 MCP 多出一条对外可达路径;
对外 Web 接口挟带 Web 层语义(按页面路径判定的数据权限、操作日志切面),
在 MCP 链路上要么不生效、要么产生误导性记录。

已知反例:oauth 侧的 `OrgFacade` / `PositionFacade` / `DictFacade` 看着可用,
实为**数据回显(Echo)机制**的实现 —— 只有 `findByIds`,底层打到 `/echo/**`,
用途是给列表页把 id 翻成名称。不可复用。

## 2. 敏感信息用白名单,不是黑名单

返回值必须显式构造,逐字段列出返回什么。

黑名单式过滤(「记得把 password 去掉」)的问题是:下游实体日后新增一个敏感字段,
工具这边不会有任何报错,直接就发给模型了,而模型输出可能进入对话记录、日志与第三方客户端。

绝不可出现在返回值中:用户口令与盐、身份证、第三方 openId、应用 appKey/appSecret、
企业统一社会信用代码、凭证表的 hash 与密文(任何工具不得读该表)、各类密钥与连接串口令。

联系方式只在「查询本人」类工具中原样返回;工具一旦会返回他人数据,必须脱敏。
裁剪尽量前移到下游 inner 接口的 VO 层,让敏感字段根本不进入 ai 服务的进程内存。

## 3. 权限必须自行判定

**数据权限拦截器对 MCP 请求完全不生效。** 它按前端页面路径查配置,而 MCP 请求的 path 恒为
`/ai/mcp`、`applicationId` 已被网关剥离,查询永远命中不了配置 → 不拼任何 where 条件 →
即「放行」而非「拒绝」。

凡是能读到调用者本人之外数据的工具,都要在 `ai/tool` 内显式判权。
租户级隔离不受影响,由数据源切换保证。

## 4. 能力层不得出现 MCP SDK 类型

`ai/tool` 下的方法签名中不得出现任何 MCP SDK 类型,协议适配一律留在 `ai/mcp`。
这条已验证过一次:传输层由有状态换为无状态时,`ai/tool` 代码一行未改。

## 5. 返回规模必须有上限且显式标记截断

凡可能返回多条记录的工具:强制或默认时间窗,拒绝无边界查询;限制条数;
**命中上限时在返回值里显式带出截断标记与真实总数**。

第三条最容易省:静默截断的结果会被当成全量推断,于是「本周没人动过这个配置」这类结论就出来了。

## 6. 降级不得伪装成鉴权失败

取数失败要按**原因**回给模型。三类必须可区分:**下游不可用/超时**、**无权限**、**数据本身就没有**。

模型看到「无权限」会换个问法绕,看到「没有数据」会下结论说「该时段无记录」,
看到「服务不可用」才会说「暂时查不到,请稍后重试」。把前者说成后者,产出的是一句自信的错误结论。

落法:Facade 返回超时语义时,返回值的错误语义必须是「上游暂时不可用」,
**不得回退成空列表或空对象** —— 空集合与「确实没有数据」在模型眼里完全一样。

## 7. 声明为可选的入参,链路每一层都要真的可选

`inputSchema` 里不在 `required` 中的参数,模型会理直气壮地省略。而
**HTTP Interface 的 `@RequestParam` 默认必填**,传 null 会抛 `Missing request parameter value`,
必须显式写 `required = false`。

**单元测试挡不住它** —— 工具层测试 mock 掉 Facade,跨不到 HTTP Interface 那一层。
守护放在 `thinglinks-ai-server` 的契约测试(该模块是唯一同时依赖 base 与 system 两个 `cloud-impl` 的地方),
并且每个带参工具都要用空参数 `{}` 真机验一次。

## 8. 只读

写操作一律走「动作草案 + 人在原页面确认」,不经模型直接执行。

明确禁止包装成工具:设备下发、Groovy 脚本执行(包装它等于把任意代码执行交给模型)、
时序库的建库建表改列与写入。
