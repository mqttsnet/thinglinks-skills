# 客户端接入与连通性自查

## 三步接入

1. **生成凭证** —— 控制台「个人中心 → MCP 凭证」新建,得到形如 `tl_mcp_xxxxxxxx` 的字符串。
   凭证与**本人 + 当前企业**绑定;只在创建时可见一次,泄露后到同一页面吊销
2. **配置客户端** —— URL 指向 `/ai/mcp`,`Authorization: Bearer tl_mcp_xxxxxxxx`,
   传输协议选 **Streamable HTTP**(不是 SSE)。服务无状态,不需要会话保持
3. **验证** —— 发一次 `tools/list`,能列出工具即接入成功

```json
{
  "mcpServers": {
    "thinglinks": {
      "url": "https://<域名>/api/ai/mcp",
      "headers": { "Authorization": "Bearer tl_mcp_xxxxxxxx" }
    }
  }
}
```

请求头要同时接受 `application/json` 与 `text/event-stream`。

## 连不上时按这个顺序查

| 现象 | 多半是 |
| --- | --- |
| 连接失败、服务端日志干净 | 路径不对。对外 `/ai/mcp`,网关 `StripPrefix=1` 后服务侧 `/mcp`,三处常量要一致 |
| 401 且带 `WWW-Authenticate` | 凭证本身的问题:写错、已吊销、不属于当前企业 |
| 503 且带 `Retry-After` | 校验链路暂时不可用,不是凭证问题,**不要去重置一把有效的凭证** |
| 能连上但只看到两三个工具 | 客户端缓存了旧的工具清单,重连或重启客户端 |

401 与 503 分流是有意的:两者混在一起时,system 服务抖一下,用户会去重置一把完全有效的凭证。

## 客户端只缓存工具清单

无状态传输下动态增删工具不可靠 —— 客户端不会重新拉取。因此**不要用「没有某项数据就不注册这个工具」
的设计**:能力集必须在启动时确定,运行期是否有数据由返回值表达,不由工具的存在与否表达。
