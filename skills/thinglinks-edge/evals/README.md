# 接入与维护行为用例

`evals.json` 使用虚构设备与观测，检查助手的选择、配置引导和结论；不连接真实设备、不创建容器、不下发命令。
这套用例不是 Edge 产品集成测试，也不证明任何真实环境已经接入。

## 执行方式

1. 新上下文只给用户 prompt、fixture 和允许读取的技能；不要给 assertions 或预设结论。
2. 要求助手给最小下一步、缺少的信息、可完成动作与结论；记录加载的专题与工具选择。工具结果通过 fixture 提供。
3. 评估者逐条核对 assertions，保存原回答、是否满足及原因。未运行写“未运行”，不能把 JSON 解析或链接通过当行为通过。
4. 基线用当前已有 Cloud/workspace/AI 技能但不提供 Edge 专题；改版后在同样任务下加载 Edge。新场景用于防止只记住一份回答。

每次修改专题时至少重跑对应案例。普通请求以可执行操作为主；开发/维护者才需要源码入口。不要为通过测试臆造 Edge MCP、历史版本查询参数或已有设备操作授权。

## 覆盖范围

- 1–3：从零接入、现场状态和控制/恢复三组基线任务。
- 4–8：模型版本、真实工具能力、OPC UA 构件、协议限制、仅变化采样。
- 9–12：网络执行位置、HTTP 推送、补传证据、升级旧流程。
- 13–16：完整映射示例、设备直连路由、分阶段引导、Cloud 回执关联。
- 17–18：中断恢复操作与备份预览语义、非零起点的可导入点表。

fixture 中实际工具入参仍以运行环境 schema 为准；示例字段不授权查询其他租户或真实设备。目录/JSON 检查可用仓库现有校验器和标准 JSON 工具，行为判断需要阅读真实回答。
