# 从设备到 Cloud 的最短接入路径

## 先获得够用的信息

先识别已有部署还是从零部署。仅问会阻塞下一步的信息，通常先确认设备协议/型号、现场地址、是否已有 Edge 实例。系统可读取的值主动读取；密码、私钥和网关密钥由用户填入正式配置页，不要求贴到对话。

| 信息 | 从哪里取得 | 用途 |
| --- | --- | --- |
| Edge 地址、版本、目标实例、运行镜像 | 管理台/部署清单 | 确认功能和网络执行位置 |
| 设备型号、协议、连接方向 | 手册、现有配置 | 选择模板，决定监听还是主动连接 |
| IP/端口/站号或 NodeId/PLC 地址 | 现场参数与点表 | 先读一个真实点，不猜厂商格式 |
| 数据类型、字节序、倍率、偏移、单位 | 点表及仪表显示 | 校验解码与换算 |
| Cloud 网关与子设备标识、产品、绑定版本 | Cloud 设备详情 | 拓扑和模型映射 |
| 是否需要设备控制 | 用户任务 | 采集先完成，控制按支持范围单独验证 |

没有 Edge 时转 [部署维护](operations.md)。已有 Edge 时直接继续接入，不重复创建部署或实例。

## 页面操作顺序

1. 在“实例”确认目标运行实例及现场网络条件；在“流程模板”选择对应协议。
2. 查看所需组件，完成固定版本批准、策略下发、安装与实际加载检查。缺组件按 [协议能力](protocols.md) 处理。
3. 配置连接和一个点位。Modbus-TCP 可先用“试读一次”：无需 Cloud 身份，仅执行一次 FC3/FC4，额外建立 TCP 连接，先确认不会挤占单连接设备的现有采集。其他协议当前的点表预览不是设备试读。
4. 比对原始值、解码值与设备实际显示。不能只看节点变绿。错一个数量级时先查类型、地址、字节序和倍率。
5. 核对 Cloud 子设备已登记、绑定已发布版本且属于当前网关；Edge 本地 `tl-device` 登记不会自动替代这一步。
6. 在“云连接”填写分配给网关的 MQTT 地址与接入配置。已有配置只改需要的字段；查看保存后的实际连接状态。
7. 在模板明确填写**子设备产品标识和绑定版本**，读取物模型，选择服务与属性编码。名称只是显示文字；离线手填保持“未校验”说明。
8. 预览生成流程，默认追加到目标实例。若流程修订冲突，重新读取和预览；不要为绕过冲突改为全量替换。
9. 部署持续采集，观察新值及时间；再核对 Cloud 影子、对应时间窗历史与独立在线状态。需要控制时转 [命令](commands.md)。

## Modbus 点表示例：先确认手册，再给配置

用户给“40001 电压、40003 电流”时，还缺功能码、编号方式、宽度、数据类型与字节序。
**只有手册已确认采用常见五位保持寄存器编号且使用 FC3**，才能换算为协议地址 0 和 2。
若又确认两点均为 32 位、设备允许连续读，则从 0 读 4 个寄存器；两个 16 位点则可能从 0 读 3 个寄存器，中间空隙是否允许读取仍需核对。

示例已知条件：FC3、五位手册编号、两个无符号 32 位点、字节序 ABCD、设备允许跨此范围，Cloud 已定义 `electrical.voltage/current`。

| 手册地址 | 相对偏移 | 类型 | 倍率 | 偏移 | Cloud 属性 | 单位 |
| --- | --- | --- | --- | --- | --- | --- |
| 40001 | 0 | uint32be | 0.1 | 0 | voltage | V |
| 40003 | 2 | uint32be | 0.001 | 0 | current | A |

试读电压原值 2301，换算应为 230.1 V；结果应再与现场仪表核对。以上参数只适用于这些明确条件，不作为其他电表的默认值。
这里的 uint32 + ABCD 在页面/导入中写 **`uint32be`**，不能写未支持的 `uint32`。导入必须有五列表头，顺序固定；单位从手册和物模型核对，不加成第六列。

若已设置起始协议地址 0、读取数量 4，选择“相对偏移”导入：

```csv
source,property,dataType,scale,offset
0,voltage,uint32be,0.1,0
2,current,uint32be,0.001,0
```

| 导入模式 | source 列含义 | 起点不为 0 的例子 |
| --- | --- | --- |
| 相对偏移 relative | 相对已设置读取块起点的寄存器偏移 | 起点 100 时填 0、2，读取数量先设 4 |
| 绝对协议地址 absolute | 0 起始协议地址，预览计算连续范围 | 填 100、102，计算起点 100、数量 4 |
| 五位手册编号 manual | FC3 40001 基址或 FC4 30001 基址 | FC3 填 40101、40103，计算起点 100、数量 4 |

输出可直接导入的点表时，始终写明选择的模式、读取起点/数量，并带表头和实际支持的类型编码；手册的宽度/字节序描述先翻译成页面类型。

试读会额外建立 TCP 连接并执行一次 FC3/FC4 请求。单连接设备先核实是否会影响现有采集；不能把试读变成扫描整个网段。试读未清理时使用原任务的“重试清理”，不反复创建任务。

## 接入完成的证据

| 阶段 | 至少核对 |
| --- | --- |
| 现场读取 | 正确设备/地址、原始样本、时间、质量 |
| 解码映射 | 类型、字节序、单位、倍率/偏移与实际量一致 |
| Edge 持续采集 | 目标实例/设备/点位出现新的有效样本 |
| Cloud 数据 | 同一子设备、绑定版本、服务属性的新影子值；对应时间窗历史可查 |
| Cloud 状态 | 网关与子设备状态分别核对，状态逐设备回执确认 |
| 生命周期 | 对需要的断连/恢复场景单独验证；不为普通试读擅自中断生产 |

只有配置预览时说“配置已准备”；只有本地试读时说“设备试读通过”；按实际完成阶段汇报。用 [信息表](../assets/device-intake.md) 交接多人维护的现场。
