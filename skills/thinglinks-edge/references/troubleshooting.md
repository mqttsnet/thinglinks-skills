# 按证据定位与维护

## 先确定范围，再选一条最短检查链

记录目标实例、设备/网关标识、故障起点和时区、最近变更。比较一台正常设备或同网关少量设备，判断是单点、单流程、单设备、实例还是整个网关故障；不要一开始导出全库或扫描整网。
读取现有证据后，提出能区分两个最可能原因的下一步。检查成功继续往后，检查失败就在该层修正并回读验证。

| 现象 | 优先证据 | 下一步/维护方向 |
| --- | --- | --- |
| 模板不可部署、缺节点 | 组件固定版本、批准/有效策略、实例加载类型 | 修复具体缺项，不重装整个 Edge |
| 设备连接失败 | 执行实例、连接方向、映射协议、实际端点和错误 | 从真正执行采集的实例确认路径；宿主能通不证明容器能通 |
| TCP 连上没有数据 | 设备主动上报还是请求应答、分帧、原始报文 | 需要查询帧的设备补相应请求流程 |
| 数值偏大/偏小/乱码 | 原始寄存器/字节、地址基准、宽度、符号、字节序、倍率 | 先修解码再改模型；不拿调倍率掩盖错误类型 |
| 一个点停止更新、其余正常 | 各点所属采集来源、最近样本/质量、流程变化 | 定位该来源，不把设备总体在线当每个点健康 |
| Edge 有值、Cloud 没值 | 子设备/网关归属、绑定版本/编码、发布与积压 | 按 [云边对齐](cloud-integration.md) 查第一段未确认链路 |
| Edge 有新值、Cloud 离线 | 网关状态、观察者来源、拓扑查询与逐设备状态响应 | 按 [状态](presence.md) 查独立状态通路 |
| 设备断开却仍在线 | 其他健康来源、旧模板、协议错误分类、租约 | 不把任意 Catch 错误变成整设备 OFFLINE |
| 重连后积压不下降 | 云配置实际状态、spool/replay、发送错误、磁盘/容量 | 查补传失败原因；不清空缓存“修复”积压 |
| 本地历史为空 | history.enabled、时间窗、点位标识 | 未启用历史不是采集故障；Cloud 历史另查 |
| 云控超时/重复消费者 | 原命令与租约、绑定冲突、设备读回、回执状态 | 按 [命令](commands.md) 处理 unknown，避免再次写入 |
| OPC UA 安全连接失败 | 节点/原生构件、CA/CRL、URI、证书时间、策略 | 区分构件与信任问题，不关闭校验 |
| HTTP 推送返回 503 | 流程运行代次、有效点位、Manager 接收/超时 | 查接受失败；设备按约定重试可能产生重复样本 |
| 升级后编辑器 401/403/502 | 用户/实例授权、编辑器解锁、实际来源端口、代理网络 | 先分认证与连通，不盲目改全局 CORS 或重建实例 |
| 实例记录在但容器缺失 | 数据目录、实际容器 ID、状态/操作记录 | 保留数据，核对受支持恢复/重建路径 |
| 恢复后 Manager 拒绝启动 | 原密钥、目录布局、事务状态及恢复错误 | 走受支持 recover；不删事务/数据库绕过 |

## 可用的观测入口

优先使用用户已登录的 Edge 控制台。API 是后台核对入口，不是新 MCP 工具；前缀以实际 basePath 为准，沿用正式会话和权限，不从数据库提取令牌。

| 入口 | 用于核对 | 边界 |
| --- | --- | --- |
| `GET /healthz` | 管理服务健康 | 不证明实例或协议健康 |
| `GET /api/cloud` | 脱敏云配置、status、spool、replay、outages | 不暴露/重建设备密码 |
| `GET /api/field/devices`、`/api/field/tags` | 可见实例的台账、值、质量与状态 | 带实例参数仍受实例权限校验 |
| `GET /api/field/history` | 指定 instanceId/nodeId/tagId 的本地历史 | enabled=false 与无数据区分 |
| `GET /api/field/southbound?instanceId=…` | 原生流程的尽力设备探测 | managed=false，不与可靠台账相加 |
| `GET /api/nodes/inventory/:id` | 指定实例的实际组件清单 | 核对版本、必需节点类型和健康状态 |
| `GET /api/commands` | Edge 命令及回执状态 | 使用管理会话与可见实例范围，不以实例接入令牌替代 |
| `GET /api/instances/:id/protocol-diagnostics` | 已有试读任务与清理状态 | 需要 instance:operate；读取不会重新试读 |

实际单次动作：Modbus 试读在 `/api/instances/:id/protocol-diagnostics/modbus-tcp`；DNS/TCP/时钟诊断在 `/api/diag/probe`；诊断包在 `/api/diag/bundle`，均为 POST 并要求相应权限/CSRF。
端点诊断由 Manager 执行，只证明该位置的 DNS/TCP/时钟结果；不能替代 Node-RED 实例到 PLC 的协议读写。试读会创建临时流程并连接指定设备，需处于用户所要求的接入/诊断范围。
诊断包可能含业务信息，只提取当前问题需要的脱敏片段；不公开上传整包、环境变量、数据库或完整容器 inspect。

## 修复与交接的闭环

一次只修改能解释现象的配置，记录前值、后值及作用对象；涉及重启/替换/恢复时说明影响。回读保存值并验证运行结果，区分“文件改了”“服务加载了”“设备恢复了”。
如果现有入口不足以证明根因，给维护者：对象、时间窗、最后正常/首次异常、原始错误、已排除层、下一条证据请求。源码定位见 [开发入口](development.md)。
不要把现场维护演变为全量安装、刷新全部凭据、删除实例或修改共享 Cloud 配置；确有需要时以具体证据提出最小操作。

依据：Edge `apps/manager/src/http/edge/field.ts`、`http/cloud/config.ts`、`http/diag/`、`http/nodes/catalog.ts`、`http/instance/protocol-diagnostics.ts`（后几项均在 `apps/manager/src/` 下）。
