# 协议选择与配置边界

以下为 2026-09-14 工作树能力，落地核对当前组件目录、模板修订与实例加载状态；组件可用不代表每种设备/固件都已验证。

| 协议/模板 | 接入配置重点 | 控制与限制 |
| --- | --- | --- |
| TCP | 主动连接或监听；LF/CRLF 或固定字节帧；JSON 路径/二进制偏移 | 通用控制要求约定 JSON 请求与匹配应答；不是任意私有协议驱动 |
| UDP | UDP 入站映射；一报文一帧；JSON/二进制解析 | JSON 应答及独立应答端口；静默默认不代表离线 |
| HTTP GET 轮询 | 设备 URL、周期、请求超时、JSON 路径、认证/TLS | 控制为独立设备 POST 接口及明确执行确认 |
| HTTP POST 推送 | 实例真实 HTTP-node 路径、外部设备入口、认证/TLS | 新模板 Manager 接受有效点位才返回 202；失败可返回 503；均不证明 Cloud 落库 |
| Modbus-TCP | FC3/FC4、站号、0 起始协议地址、连续寄存器块、宽度与字节序 | **新内置模板禁用控制**；组件断连后可能迟到写入，旧流程不会自动修复 |
| OPC UA 兼容采集 | `node-red-contrib-opcua` 标量读/订阅、NodeId、类型和质量 | 此模板控制关闭 |
| OPC UA 安全采集控制 | `@tier0/opcua-client`、证书/信任/身份、原生构件、标量点位 | 验证目标及 Good 写结果；平台/证书组合分别验收 |
| S7 | IP、Rack/Slot、数据块访问、PUT/GET 权限、变量表 | 已实现地址/类型范围内单点写；等待驱动完成结果 |
| Modbus-RTU | 协议包存在，但受管实例缺受控串口透传 | blocked；不以 privileged 或挂载整个 `/dev` 绕过 |
| CoAP、BACnet、IEC104 | 当前扩展候选 | 无已验证固定驱动/可部署内置模板，不作开箱支持承诺 |

MQTT/WS 设备直连 Cloud、GB28181/ONVIF 视频按 Cloud 域处理。Node-RED 有某类通用节点，也不等于 Edge 已提供其受管模板和完整交付链路。

## 组件是否真的准备好

固定组件核对入口：Edge `apps/manager/src/core/protocols/catalog.ts`。
当前首批种子：`node-red-contrib-modbus@5.60.2`、`node-red-contrib-opcua@0.2.355`、`node-red-contrib-s7@3.1.3`。
安全 OPC UA 另用 `@tier0/opcua-client@0.6.0`，不由首批三组件离线种子自动保证完整依赖及原生运行环境。

核对顺序：原包版本/完整性 → 完整依赖 → 批准 → 实例有效策略 → 安装版本 → 必需节点类型实际加载。
固定版本不匹配或缺节点时先解决组件层，不调整设备点表“试运气”。批准/策略修改对已有实例的生效方式见 [运维](operations.md)。

## 地址、网络与数据换算

- Modbus：FC3 常见手册 40001、FC4 常见手册 30001 才按对应基址换算；厂商其他编号按手册。一次最多 125 个连续寄存器；寄存器数不是点数。32 位点占两个寄存器，跨空洞不被设备允许时拆流程。
- Modbus 点表类型编码是 `uint16be/le`、`int16be/le`、`uint32be/le`、`int32be/le`、`float32be/le/swap`（斜杠表示各个完整后缀选项）。uint32 + ABCD 对应 `uint32be`；导入不能直接填 `uint32` 或 `ABCD`。五列表头、地址模式和完整例子见 [接入引导](onboarding.md)。
- TCP 主动连接模板默认等待设备发数据。需要请求帧才返回数据的仪表，要补厂商请求逻辑；连接成功但没数据不一定是物模型问题。
- TCP/UDP 监听需要对应传输类型的实例端口映射。设备连接 Edge 的现场网卡地址；`0.0.0.0` 是监听范围，容器的 `127.0.0.1` 是该容器自身。
- HTTP 设备入口与管理登录入口不同。不要把管理 Cookie/编辑器口令给设备，也不要通过开放管理接口代替设备认证入口。
- OPC UA NodeId 是完整标识，不是显示名称；字符串 NodeId 中有意义的空白不应随意修剪。先校验质量再使用值，不把 Bad/不完整采样置零上云。
- S7 如 `DB1,REAL0` 的逗号属于地址；CSV 要加双引号，Excel 可按列粘贴。访问权限和数据块方式以设备型号/手册为准。
- 上报 `工程值 = 原值 × 倍率 + 偏移`；控制反算 `(工程值 - 偏移) / 倍率`。拒绝不匹配类型、非有限值、越界及无法精确表示的数据；不静默截断/限幅。大于 JS 安全整数范围的计数按设备协议保留字符串。

## OPC UA 证书与原生构件

先区分节点未加载、原生构件不匹配、TCP 不通、信任/身份/吊销失败和 NodeId 权限问题。
原包的完整 DER 链互操作缺陷有独立兼容构件 `thinglinks-opcua-native 0.6.0-chain.1`；不修改原 npm 包的版本或完整性。
修复是否生效取决于**实际运行镜像**：检查镜像标签与只读构件清单，而不是只看 npm 安装成功。

当前 `scripts/opcua-native/manifest.json` 的构建组合：5.0.4-24-minimal 的 Linux musl ARM64/x64，5.0.7-24-minimal 的 Linux musl ARM64；5.0.7 x64 不在此构建配置内。Node/基础镜像以清单固定值为准；这张表是构建范围，不是全型号现场验收。
普通官方 Node-RED 镜像不会自动带此构件。不要关闭证书校验、降级安全模式，或把可写实例目录中的二进制当作受信覆盖。

需要检查的实际证据：服务器地址、端点安全策略、应用 URI、CA/CRL、证书有效期、账号权限、节点质量、运行镜像与架构。私钥留在正式凭据存储中。

兼容镜像的定位：从目标部署的镜像清单取得完整镜像引用，再核对其 `com.mqttsnet.thinglinks-edge.opcua-native` 标签和构件 manifest；构建来源是 Edge `scripts/opcua-native/README.md` 及 `manifest.json`。本 skill 没有确认一个可供所有环境直接拉取的公开兼容镜像 tag，不能把文档中的 `local/…` 构建示例说成已发布制品。没有匹配制品时明确需按受信构建/交付流程准备。

## HTTP 推送重试的实际边界

当前通用上行不提供设备事件 ID 去重合同。202 后不因“尚未查到云数据”立即重发；503/网络超时时按设备已有协议的有限退避重试，可能重复。具体间隔/次数取决于设备要求，未确认前不承诺某组值能保证可靠且不重复。
不能擅自加 `eventId` 字段声称平台会去重。若业务要求不重复处理，需另行设计和验证端到端事件身份/去重，超出当前模板开箱能力。
