# 设备在线、采集来源与云端状态

## 三种状态分别判断

| 对象 | 证据 | 不能推出 |
| --- | --- | --- |
| Node-RED 实例/流程 | 容器运行、流程租约 | 设备正在返回有效数据 |
| 现场设备 | 当前代次的有效样本、协议明确不可用事件、多来源合并 | MQTT 或 Cloud 状态已同步 |
| Cloud 网关/子设备 | 网关连接；子设备 `topo/update` 逐项成功响应 | 每一个现场点或采集来源均正常 |

`/datas` 和 `topo/update` 是独立链路。Cloud 子设备离线但 Edge 有新采样时，优先查归属和状态同步，不直接下结论说设备物理断网。

## 当前新模板的来源规则

- 每条采集流程有独立观察者，同实例与跨实例都保留来源关系。**任一来源在线则设备保持在线；全部已知来源明确不可用才请求离线；没有在线来源但还有未知来源则等待采集确认。**
- 样本和离线事件带观察者、运行代次与递增序号。旧代次、重复或倒序事件被拒绝，不能覆盖恢复后的新样本。
- 观察者运行租约标记流程是否还在工作。续约只证明流程运行，不刷新设备采样时间、不生成上云值、不单独建立在线证据。
- 租约失效、删除流程、确认实例停止/移除与现场设备静默不是同一类原因。来源登记不完整/容量不足时保留冲突或未知，不能丢掉来源后草率判整机离线。
- 离线观察可重发以免一次请求丢失；恢复后停止重发，迟到序号不覆盖新采样。Manager 重启不会把旧台账直接恢复为在线证据。
- 网关 MQTT 重连后，需要新的有效采样建立在线证据；旧缓存、历史补传和绿色连接灯不能代替。

周期参数以当前模板为准：目前流程通常每 10 秒续约、60 秒租约到期，检查轮次与云端重试还会增加延迟。它不是全协议统一的“60 秒无数据即离线”。

## 各协议事件的含义

- S7 仅变化上报仍周期真实读取，未变化样本可更新现场值/时间/在线证据但不重复入云批次；当前每 60 秒完整同步用于修补提交丢失。不要改成仅凭变化才能证明在线。
- OPC UA 订阅没有新通知，不应制造新样本；云连接恢复后仍需新有效采样。NodeId 不存在、质量错误、账号无权限与物理断网要分别诊断。
- UDP/HTTP 推送默认没有通用在线连接语义。只有确认设备固定周期上报时才显式配置静默时限，并结合允许延迟；事件驱动设备不套统一超时。
- TCP/工业节点的状态或 Catch 错误需按具体组件语义分类。不是每个解析错误都能转换为整台设备离线。

## “一条流程断了”怎么查

1. 固定 Cloud 子设备与故障时间，列出该设备涉及的实例和采集流程，不只看当前打开的一个流程。
2. 核对各来源最近有效样本、协议错误、租约、运行代次，以及是否使用新模板。另一来源有真实健康数据时，整台设备不应因单来源断开而离线；该来源所负责的点仍可能停止更新。
3. 在现场页核对 `presenceState`：`unknown` 是等待确认，不是已证实在线/离线。不要只读取兼容布尔字段。
4. 核对 Cloud 网关归属查询、`topo/update` 请求和对应设备响应；部分失败不能以批次已发送代替成功。
5. 若只有旧流程，没有观察者元数据，先明确能力缺口和重新部署影响；更新 Manager 并未升级流程。

## 旧流程与恢复

新旧流程混用时，有观察者的设备状态不会被旧无元数据状态随意覆盖。需要参与聚合的来源应一起纳入新模板；不为快速修复把全部节点错误连到 `status:false`。
现场断开/恢复验收应保持 Node-RED 和 MQTT 运行，仅在已允许的设备或模拟器范围切断协议连接，再确认离线、恢复新样本、Cloud 逐设备响应。多来源验收分别切一条和全部来源。
