# GB28181 信令层(thinglinks-video-biz-protocol)

包根 `video/gb28181/*`。SIP 协议栈之上的租户路由、信令收发、事件化、级联与对讲。SIP 栈由 `SipLayer` 启动(5060 UDP + TCP,所有租户共用)。

## 入站第一步:租户路由

`SIPRequestProcessorParent#handlerTenantId` 依次尝试:① Request-URI 里的 sipId 精确查 Redis(`TenantSipConfigProvider.resolveBySipId`)② FROM 头里的设备编号查同一张表 ③ SIP 域匹配(设备编号前 10 位 = `sipDomain`)④ 全局只有一份配置时直接命中。都查不到、或缓存缺 `tenantId`,直接拒绝。

- requestSipId 与 `video_sip_config.sip_id` 不一致**只告警不拒绝**。常见原因是把设备编号填进了平台 `sip_id`,表现为设备回 200 OK 后立刻 BYE。
- 路由缓存由 XXL `refreshSipTenantConfigCacheJobHandler` 刷新;改了 SIP 配置不生效,先看这个任务。
- 入站报文有两层字节上限(整条报文 / MESSAGE body,Nacos `user-settings.*`);MESSAGE 超限在租户路由之前就回 `413`。改阈值要重启。

## transmit 管线(信令收发)

- `transmit/request/impl/**`:按 SIP 方法分 processor(Register / Subscribe / Notify / Message…)。MESSAGE 按 body 根元素分四个包,再按 CmdType 细分 handler:
  - `message/query/cmd`:收到的 `<Query>`(`*QueryMessageHandler`:Catalog / DeviceInfo / DeviceStatus / RecordInfo / Alarm)
  - `message/response/cmd`:收到的 `<Response>`,即我方查询后设备的应答(`*ResponseMessageHandler`:Catalog / DeviceInfo / DeviceStatus / DeviceControl / RecordInfo / MobilePosition / PresetQuery / Broadcast / ConfigDownload / Alarm)
  - `message/notify/cmd`:`<Notify>`(Keepalive / Catalog / MobilePosition / MediaStatus / Alarm)
  - `message/control/cmd`:上级平台发来的 `<Control>`(`DeviceControlFromSuperiorMessageHandler`)
- `transmit/response/impl`:出方向应答;`transmit/callback`:请求-应答关联;`transmit/observer`:`SIPProcessorObserver` 统一分发入口;`SIPSender` 统一发送。
- `factory/GBStringMsgParser`:报文解析;`auth/DigestServerAuthenticationHelper`:摘要认证。

## 事件体系(信令事件化,18 类事件)

`gb28181/event/` 根下 **18 个 `*Event`**:会话(`InviteSessionCreated/Changed/Closed`)、点播(`PlayRequested` / `PlayFailed` / `PlaybackRequested` / `PlaybackControl`)、流(`StreamReady` / `StreamClosed`)、SSRC(`SsrcAllocated` / `SsrcReleased` / `SsrcPoolExhausted`)、RTP 端口(`RtpPortAllocated` / `RtpPortReleased`)、指令(`SipCommandSent` / `PtzCommandExecuted` / `DeviceControlExecuted`)、`RecordQueryCompleted`。

配套子包:`source ×18`(每个事件一个 `*EventSource`)、`listener ×11`、`publisher ×7`、`subscribe ×3`。**数事件看根下的 `*Event`,不要把 source 一起数进去。**

- 信令处理器只**发事件**,业务副作用(缓存刷新 / 状态落库 / 通知)走 listener —— 加联动行为时**新增 listener,不改 processor**。
- **协议事件不往下渗透**:GB28181 事件的定义、发布、监听都在 biz-protocol 内闭环;要通知 biz,用 entity 层的通用事件(如 `DeviceInfoOnlineEvent`)。

## 指令与会话

- `cmd/`:`PlayCommander` / `QueryCommander` / `PTZCommander` / `BroadcastCommander` / `SubscribeCommander`,报文由 `SipMessageBuilder` / `SdpBuilder` 组装,控制类 SN 由 `DeviceControlSnGenerator` 生成。
- `session/`:`InviteSessionService`、`RtpPortService`、`SsrcNegotiationService`;SSRC 池在 biz `manager/ssrc`,耗尽发 `SsrcPoolExhaustedEvent`。

## 版本与厂商适配(三套,别混)

- **国标版本**:`protocol/GbProtocolAdapter` → `Gb2016ProtocolAdapter` / `Gb2022ProtocolAdapter`,`GbProtocolAdapterFactory` 选实现,设备版本统一由 `GbProtocolVersionResolver` 解析。
- **厂商设备行为**:`device/DeviceAdapter` → `Hikvision` / `Dahua` / `Uniview` / `DefaultDeviceAdapter`,`DeviceAdapterFactory` 按注册时的 manufacturer 或 User-Agent 选。
- **厂商协议扩展**:`video/protocol/VendorProtocolAdapter`(`vendor/` 下 `Default` / `Hikvision` / `DahuaGb28181VendorAdapter`),`VendorProtocolAdapterFactory` 按厂商 + 版本匹配,找不到回落默认。

## 级联(下级 → 上级平台)

- 注册与指令:`platform/PlatformRegisterService`(向上级注册,失败按 `sip.register-time-interval` 重试)、`PlatformCascadeCommander`;推给上级的目录 / 通道存 `video_platform_catalog` / `video_platform_channel`。
- 上级发来的请求在 `service/cascade` 处理:`SuperiorPlatformRequestAuthenticator`(认上级)、`SuperiorChannelAuthorizationService`(把上级看到的通道编号换回内部设备与通道,并判定该通道确实分给了这个平台)、`SuperiorPlatformInviteService`(上级点播)、`CascadeRecordInfo*`(上级录像查询)。
- 上级的设备控制**必须**先经 `SuperiorChannelAuthorizationService` 换号与授权,控制值只接受 `DeviceControlTypeEnum` 里的子元素。跳过这一步,任何注册上来的上级都能控制我方全部摄像机。

## 语音广播 / 对讲

`BroadcastService`(`/broadcast/start|stop|status`)只建立「浏览器推流 + 设备反向 INVITE」所需的会话;设备 INVITE / ACK / BYE 的校验与 RTP 推送在 `service/talk`(`DeviceTalkInviteService`、`Talk*RequestValidator`、`AudioTalkRtpService`、`AudioTalkCleanupService` 等)。多协议分派见 `service/stream/talk/TalkProtocolStrategyRegistry`。

## ⚠️ 反幻觉

- `message/query/cmd` 与 `message/response/cmd` 方向相反:前者是别人查我方,后者是我方查询后收到的应答,找 handler 时别看反。
- 设备目录 / 状态的缓存刷新由事件 listener 驱动,不要在 handler 里直写缓存。
- `DeviceNotFoundEvent` 已删除,别再引用。
