# GB28181 信令层(thinglinks-video-biz-protocol)

包根 `video/gb28181/*`。SIP 协议栈之上的信令收发、事件化与级联。

## transmit 管线(信令收发)

- `transmit/request/impl/**`:按 SIP 方法分 processor(Register / Subscribe / Message…),`message/query|response/cmd/**` 按国标指令细分 handler(Catalog / DeviceInfo / DeviceStatus / RecordInfo / MobilePosition / Preset / Broadcast / ConfigDownload…)。
- `transmit/response/impl`:出方向应答;`transmit/callback`:请求-应答关联;`transmit/observer`:`SIPProcessorObserver` 统一分发入口;`SIPSender` 统一发送。
- `factory/GBStringMsgParser`:报文解析;`auth/DigestServerAuthenticationHelper`:摘要认证。

## 事件体系(信令事件化,38 类)

`gb28181/event/{source ×18, listener ×9, publisher ×7, subscribe ×3}` + 流/SSRC/命令事件(`StreamReadyEvent` / `StreamClosedEvent` / `SsrcAllocatedEvent` / `SsrcReleasedEvent` / `SsrcPoolExhaustedEvent` / `SipCommandSentEvent`)。
模式:信令处理器只**发事件**,业务副作用(缓存刷新/状态落库/通知)全部走 listener——加联动行为时**新增 listener,不改 processor**。

## 指令与会话

- `cmd/*Commander`:Play / Broadcast / Query 等下行信令指令封装。
- `session` + `ssrc`(biz 侧 manager):点播会话与 SSRC 池分配/释放,耗尽发 `SsrcPoolExhaustedEvent`。

## 协议适配(版本差异)

`gb28181/protocol/`:`GbProtocolAdapter` SPI + `Gb2016ProtocolAdapter` / `Gb2022ProtocolAdapter`——国标 2016/2022 差异收敛在 adapter,新版本=新实现,不动 transmit 管线;厂商级差异另见 [media-access.md](media-access.md) 的 `VendorProtocolAdapterFactory`。

## 级联(platform)

`gb28181/platform` + biz `manager/platform`:上级平台注册、目录(`video_platform_catalog`)与通道(`video_platform_channel`)推送、订阅(`video_notify_subscription`)。

## ⚠️ 反幻觉

- 同名 ResponseMessageHandler 在 `query/cmd` 与 `response/cmd` 两个包都有(查询应答 vs 控制应答),引用时核对完整包路径。
- 设备目录/状态的缓存刷新由事件 listener 驱动,不要在 handler 里直写缓存。
