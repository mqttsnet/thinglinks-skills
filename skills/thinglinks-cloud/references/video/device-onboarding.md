# 视频设备接入指南(GB28181 / RTSP / ONVIF / JT/T 1078)

帮用户把设备接上平台时按这份走:先确认平台侧前置,再按协议给出**设备侧要填的值**和**平台侧要建的档**,最后按验收步骤确认。每一步卡住时的判据写在步骤里,按现象查见 [troubleshooting.md](troubleshooting.md)。

> 先让用户打开控制台的「接入协议」页(`GET /protocolAccess/list`):它实时显示本实例各协议是否可用、监听地址与端口、接入步骤;端口没起来时直接给出原因。

表格里「控制台字段」取自控制台表单文案,「后端字段」是接口字段名。

## 零、平台侧前置(所有协议)

**1. 流媒体节点**(「流媒体服务器」页),至少一台在线。设备不指定「关联流媒体标识」时用租户的默认节点。

| 控制台字段 | 后端字段 | 填什么 |
| --- | --- | --- |
| 服务器地址 | `host` | 平台访问 ZLM HTTP API 的地址 |
| HTTP端口 / 鉴权密钥 | `httpPort` / `secret` | ZLM 的 HTTP 端口与 `api.secret`;保存前点「测试连接」 |
| SDP地址 | `sdpHost` | 写进 SDP、让**设备推流**的地址,设备必须能到 |
| 流播放地址 | `streamHost` | 拼进播放 URL、给**浏览器**的地址,浏览器必须能到 |
| 是否开启自动配置 | `autoConfig` | ZLM 节点必须开启(不填按开启,保存 / 编辑时关闭会被拒绝):Hook 凭据要靠平台自动下发给节点才会激活 |
| Hook回调地址 | `hookHost` | ZLM 回调平台用的网关前缀;留空走 Nacos `media.hook-domain-prefix` |
| 多端口RTP收流端口范围 / RTP发流端口范围 | `rtpPortRange` / `sendRtpPortRange` | 收流端口段要在防火墙 / NAT 上放通 |

**2. 对设备可达的地址**:部署侧 `SIP_PUBLIC_HOST` / `SIP_PUBLIC_PORT`(GB28181 与 JT1078 都靠它),多副本各填各的。「SIP 节点」页的「接入地址」就是摄像机该填的 SIP 服务器地址 / 端口;显示「未配置」时是自动识别的网卡地址,跨网段的设备可能到不了。

## GB28181(摄像机 / NVR / 下级平台,设备主动注册)

### 平台侧:「SIP 接入配置」页

| 控制台字段 | 后端字段 | 说明 |
| --- | --- | --- |
| SIP 服务器编号 | `sipId` | 20 位数字,前 10 位是行政区划码。**不能与任何设备编号相同** —— 很多摄像机出厂把两者设成同一个值,要改设备编号;否则 INVITE 后设备立刻 BYE,前端一直转圈 |
| SIP 域 | `sipDomain` | `sipId` 的前 10 位 |
| 认证密码 | `sipPassword` | 设备注册的默认口令,AES 加密存储 |
| 注册IP白名单 | `ipWhitelist` | 留空不启用;填了只放行这些来源(单个 IP 或 CIDR),其余回 403 |
| 允许自动建档 | `allowDeviceAutoRegister` | 缺省开启;关闭后只接受设备台账里已有的编号,其余注册回 403 |
| 自动建档通道数上限 | `autoRegisterChannelLimit` | 缺省 64;自动建档的设备上报的通道数超过它时挂起目录同步 |
| 是否默认 | `isDefault` | 出站 SIP(INVITE / BYE)的 From 取默认配置 |

- 设备注册按 Redis 里的路由缓存找租户。改完配置不生效时点「刷新缓存」(或等 XXL `refreshSipTenantConfigCacheJobHandler`)。

### 设备侧(摄像机的「平台接入 / GB28181」页,各厂商叫法略有差异)

| 设备上的项 | 填 |
| --- | --- |
| SIP 服务器编号 | 平台的 `sipId` |
| SIP 域 | 平台的 `sipDomain` |
| SIP 服务器地址 / 端口 | 「SIP 节点」页的接入地址(默认端口 5060) |
| 设备编号 | 设备自己的 20 位国标编号(第 11–13 位是类型码),**不等于**平台 `sipId` |
| 注册密码 | 平台「认证密码」;设备档案里单独设了「认证凭据」则填那个 |
| 心跳周期 / 最大心跳超时次数 | 决定多久判离线,平台缺省 60 秒 × 3 次,可在设备档案里按台覆盖 |
| 传输协议 | UDP 或 TCP(信令) |

### 注册时平台依次做什么(卡住看这里)

1. **找租户**:Request-URI 的 sipId → FROM 里的设备编号 → SIP 域 → 全局唯一配置;都找不到直接拒绝(日志「未找到租户配置」)。
2. **白名单**:来源 IP 不在名单里回 **403**(日志 `[SIP白名单] 拒绝注册`)。
3. **未登记的编号**:允许自动建档就建档(角色一律是 `DEVICE`);关闭了自动建档回 **403 auto register disabled**。
4. **口令**:设备档案的 `authSecret` 优先,没有就用 SIP 配置的共享口令。报文不带认证头时回 **401** 挑战(正常流程);口令或 SIP 服务器编号不对回 **403 wrong password**。**下级平台**(`deviceRole = PLATFORM`)必须设独立口令,不回落共享口令。
5. **上线**:注册成功置在线,自动查 DeviceInfo 与 Catalog 建通道。通道数超过 `autoRegisterChannelLimit`(缺省 64)会**挂起目录同步**(日志「通道数超出自动建档上限」):大路数 NVR 就调高上限,下级平台先登记成平台。

### 设备档案里可调的 GB28181 参数(「设备信息」编辑页)

国标版本 `gbVersion`(2016 / 2022,缺省 2016)、字符集 `charset`(GB2312 / UTF-8,缺省 GB2312,中文通道名乱码时调这里)、目录 / 报警 / 移动位置订阅开关(缺省关闭)、数据流传输模式 `streamMode`(`UDP` / `TCP_ACTIVE` / `TCP_PASSIVE`)、收流地址 `sdpHost`、心跳间隔与超时次数、认证凭据、关联流媒体标识。

### 验收

设备列表显示在线 → 通道列表有通道(没有就点「同步目录」,即 `POST /videoDevice/syncCatalog`)→ 实时监控里点播出画面。

## RTSP(平台主动拉流)

「设备信息」页新增设备,接入协议选 RTSP:

| 控制台字段 | 后端字段 | 说明 |
| --- | --- | --- |
| 完整拉流URL | `protocolConfig.streamSource.url` | 含账号密码与路径,如 `rtsp://admin:pass@host:554/h264/ch1/main/av_stream`;填了优先用 |
| 设备地址 / 端口 + 账号 + 流路径 | `host` / `port` + `streamSource.username` + `streamSource.streamPath` | 不填完整 URL 时后端拼 `rtsp://账号:密码@host:port/路径`;密码填在「认证凭据」 |
| RTP传输模式 | `streamSource.rtpType` | TCP 兼容性最好,跨网 / 公网用 TCP;同网段可选 UDP |
| 设备侧回放地址模板 / 回放时间格式 | `streamSource.playbackUrlTemplate` / `playbackTimeFormat` | 配了才有「从设备回放」,模板必须含 `{startTime}`;时间格式缺省 `yyyyMMdd'T'HHmmss'Z'`(UTC) |
| 关联流媒体标识 | `mediaIdentification` | 由哪台媒体节点去拉 |

- 完整 URL 与 host + port 至少填一个,否则保存报错。设备标识不填时自动生成 `RTSP_{host}_{port}`,并建一条默认通道(通道标识 = 设备标识)。
- 建档即显示在线,之后由代理流到达与周期探测维护(见 [media-access.md](media-access.md))。
- **验收**:先在**媒体节点所在的网络**用 ffplay / VLC 直接拉一次这个地址,再到平台点播。拉流的是媒体节点,不是平台,也不是用户的电脑。

## ONVIF(发现 → 加载码流 → 导入,之后按 RTSP 拉流)

1. **扫描**:「设备信息」页打开「ONVIF 设备发现」,点「扫描 ONVIF」,走 WS-Discovery 组播 `239.255.255.250:3702`。**要求 video-server 与摄像机在同一个二层网段**:跨网段、容器 bridge 网络、多网卡时选错网卡都会扫不到(提示「未发现 ONVIF 设备」)。控制台弹窗只能从扫描结果里选;接口 `POST /onvif/profiles` 可以直接传设备 SOAP 端点 `xaddr`。
2. **加载码流**:填账号、密码,点「加载码流」(`GetProfiles`,列出主 / 子码流)。认证是 WS-Security UsernameToken,用平台本机时间生成 `Created`,不做时钟偏移补偿 —— **设备时间偏差大时认证会失败**,先让设备对时。
3. **导入**:选「关联流媒体(导入到哪台 ZLM)」,点「导入」。平台取 `GetStreamUri` 的 RTSP 地址、注入凭据,建成一台 ONVIF 设备,点播走 RTSP 拉流。
4. 云台、设备控制、录像检索(Profile G,可选功能)、告警按设备能力可用。告警订阅是 video-server 的进程内状态,重启后由对账任务重建。
5. **验收**:同 RTSP。

## JT/T 1078(车载终端)

### 平台侧

1. **服务配置**:`thinglinks.video.jt1078.signal-port`(模板 5061)、`media-port`(模板 5062,不配则实时预览与回放下发不了)、`media-ip`(留空用 `sip.public-host`)。「接入协议」页会显示两个端口有没有起来。
2. **先建档**:「设备信息」页新增设备,接入协议选 JT1078,**设备标识填终端手机号**(与终端上报的完全一致)。
   - 「认证凭据」`authSecret` 就是鉴权码;留空时鉴权码等于手机号本身 —— 开箱即用,但等于知道手机号就能接入,生产环境应按台设置。
   - 「通道数」`channelCount`(接入协议选 JT1078 后出现,必填,1~255)决定生成几个逻辑通道(标识为 `手机号_1`、`手机号_2`…);调小不会删除已有通道。
   - 手机号全平台唯一,已被其他租户占用会拒绝保存。建档时写入「手机号 → 租户」索引,终端注册靠它找租户。
3. **只能单副本部署**(见 [video.md](video.md))。

### 终端侧

| 终端上的项 | 填 |
| --- | --- |
| 主服务器地址 / 端口 | 平台对终端可达的地址 + `signal-port` |
| 终端手机号 | 与平台设备标识一致 |
| 协议版本 | JT/T 808-2013 与 2019 都支持,按报文头自动识别 |

媒体地址不用在终端上配:平台在 `0x9101` / `0x9201` 指令里带上自己的 media 地址。

### 接入过程(卡住看这里)

1. **注册 `0x0100`**:未建档回 `0x04`(日志 `[JT808] 终端未在平台建档`);成功则在应答里下发鉴权码,**此时还不算在线**。
2. **鉴权 `0x0102`**:鉴权码不匹配时回通用应答失败并断链(日志 `[JT808] 鉴权码不匹配`);通过才置在线(日志 `[JT808] 终端鉴权通过`)。
3. **点播**:平台下发 `0x9101`,终端推流到平台 media 端口,平台转封装后推给媒体节点;15 秒内流没就绪即超时。

### 验收

设备在线 → 通道列表里有 `手机号_N` → 实时监控点播出画面。

## ⚠️ 协助用户时别说错

- GB28181 的「SIP 服务器编号」和「设备编号」是两个不同的 20 位编号。
- RTSP / ONVIF 是**媒体节点**去拉流,连通性要从媒体节点所在网络验证。
- ONVIF 导入后就是拉流设备,在线显示靠探测,不靠设备注册。
- JT1078 平台不自动建档;鉴权码不是在终端上随便设的,由平台在注册应答里下发。
