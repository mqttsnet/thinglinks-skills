# Changelog

Notable changes to the ThingLinks skills. Format loosely follows [Keep a Changelog](https://keepachangelog.com/). Skills are knowledge packs, so entries describe **what an agent now knows**, not application releases.

## [Unreleased]

### Added
- `thinglinks-cloud`: `references/system/service-rpc.md` — service-to-service calls now **fork by edition**. Enterprise moved off OpenFeign to Spring HTTP Interface (`@HttpExchange` interface + `@ImportHttpServices(group=…)` registration + mandatory `@HttpServiceFallback` returning `R.timeout()`); Community still uses `@FeignClient`. Covers the connection-pool/header-propagation底座, the `@Lazy` constraint, and a 7-point checklist. Ten Feign mentions across the skill rewritten to point here.
- `thinglinks-cloud`: `references/system/job-scheduling.md` — XXL-Job. The scheduler is a separate engineering repo (`thinglinks-job`) on its own version line while the base/iot executors stay in cloud; full JobHandler inventory, and a "check the two ends connect before you blame the job" troubleshooting order (context-path in `admin.addresses`, matching `accessToken`, `EXECUTOR_IP` reachable for the reverse XXL-RPC call).
- `thinglinks-util`: `references/cloud-starter.md` (HTTP Interface wiring, the header-propagation list and its two-level fallback, HttpClient 5 pool — **`max-connections` is inert under the default LAX policy** — the two RestTemplate beans, grayscale LB, and the exact scope of the OpenFeign removal) and `references/tds-extend-db.md` (extend-database engines TDengine / ClickHouse / IoTDB, per-engine create-database options, **IoTDB's ns precision and `?sql_dialect=table` are deployment preconditions**, `DbPlusUtil` URL recognition, lowercase type-mapping keys, constant tag column names).
- `thinglinks-ai`: `references/server/protocol/resources.md` — the resource primitive alongside tools (thing-model exposed at `thinglinks://product/{productIdentification}/thing-model`, same-source fetch, error semantics), plus a runtime-side section in `orchestration/domains/device.md` on when to prefer the resource over the tool.
- `scripts/validate.mjs`: three new CI checks — relative markdown links resolve, bare `references/<x>.md` prose paths resolve, and workflow `requires` tool names are known to `orchestration/`.

### Fixed
- `thinglinks-ai`: MCP credentials are **not** view-once — plaintext can be re-read from the console at any time, so "lost it, make a new one" was wrong advice that silently breaks live clients. Documented the two client-config shapes (with/without the `mcpServers` container) and the `GET /ai/mcp/whoami` self-check for "connected but the data looks wrong".
- `thinglinks-workspace`: `thinglinks-job-pro` and `thinglinks-web-pro-visualize` were listed as Community-only directories; both are active Enterprise repos. Added the edition-divergence table (module count, RPC style, util version, plugin JDK) and rewrote the version-line section — `bump-version.sh` is a five-component orchestrator driven by `.thinglinks-product.env`, not a 10-place find-and-replace.
- `thinglinks-cloud`: `thinglinks-sop-gateway` is a submodule of `thinglinks-gateway`, not a top-level module, and `thinglinks-sop-admin` was missing entirely; added `view` / `mobile` / `generator` / `dependencies-parent`. The 65531-byte row limit is imposed by the platform for **all** engines, not by TDengine. Unit tests now run by default (the global `skipTests` is gone, so `-DskipTests` finally works). New `model/query` uplink handler. TDS failure reasons are truncated before leaving the service.
- `bifromq-plugin`: the Java target forks by edition (Enterprise JDK 25 with a build-failing enforcer, Community 17); the setting provider now serves four settings — `MsgPubPerSec` was missing.
- Ten stale `references/x.md` paths left over from the `references/` reorg, and the reference counts in `README.md` / `README.zh-CN.md`.
- A mechanical audit (class names, method names, constants, file paths, ports, numeric claims) against the live repos turned up eight more factual errors: only `lbRestTemplate` carries the context-header interceptor (the plain `restTemplate` does not, so it silently drops tenant context); the Nacos port is 8848 from the Maven filters and 18848 only under docker-compose; there are ten uplink-response handlers, not nine; GB28181 exposes 19 signalling event types, not 38; the collection-pool cache holds `DeviceActionCacheVO` and has no 10000-entry cap; `v-hasAnyPermission` is the codebase default (102 uses vs 6) and means *any* where `v-hasPermission` means *all*; IoT components never use a `src/` subdirectory unlike the Vben ones; and `.data.tsx` exports are named `editFormSchema` / `searchFormSchema` / `customFormSchemaRules`, never `createFormSchema`.
- `scripts/validate.mjs`: optional per-skill `lint.json` purity rules — declared directories are scanned for forbidden patterns (CI-enforced). `thinglinks-ai` uses it to keep its runtime-served references free of class names, module paths and SQL.
- **`thinglinks-ai`** — new skill: how an agent should drive the ThingLinks MCP server. `orchestration/` (routing by question type, cross-tool chaining, one file per capability domain — identity / org / audit / device / metric / rule / ota / view), `boundaries/` (read-only, server-injected identity, tenant isolation holds but org-level filtering does not apply, and an explicit unanswerable list), `workflows/` (answering contract, evidence rules, and 7 scenario playbooks incl. threshold audit, anomaly cross-check and fault triage), `server/` (architecture, protocol contract, tool-development hard rules, downstream `/inner/mcp` conventions, client integration, build & test). Ships `scripts/check_tool_drift.py` to reconcile the documented tool set against a live `tools/list`.
- `thinglinks-cloud`: video domain expanded to 3 references — `video.md` rewritten as overview (module split / domain map / table & cache baseline), new `video/gb28181.md` (signaling pipeline + 38-event system + cascade + Gb2016/2022 adapters), new `video/media-access.md` (ZLM hook events, stream/record, ISUP, JT1078, VendorProtocolAdapter, ONVIF); `iot/testing.md` gains bridge-execution verification.
- `thinglinks-util`: new `references/kafka-starter.md` (keyed send rules, transaction opt-in policy, `max.block.ms` fast-fail, DLT consumer baseline) and `references/databridge-starter.md` (Sink/Source/Serializer SPI, ConnectorRegistry discovery, 19-sink/3-source matrix).
- `thinglinks-web`: `iot-pages.md` — dashboard (assetStats/assetmap), product `versionOverview`, device-shadow location corrected to `device/running/`.
- All four project skills now carry a dual-line applicability note (Enterprise repo ↔ Community monorepo sub-dir) pointing to `thinglinks-workspace`; verified-against footers refreshed to 2026-06-12.
- **`thinglinks-workspace`** — new skill: dual-line repo/path locator (Community monorepo ↔ Enterprise repos), governance-file placement, version lines + `bump-version.sh`, `changelogs/` per-release layout, Nacos template placeholder rules, plus `references/security-baseline.md` (7-group hard-requirements checklist).
- `thinglinks-cloud`: `references/ws-downlink-broadcast.md` — WS downlink broadcast (`WsDeviceSessionRegistry` online registry + RocketMQ `BROADCASTING` fan-out + local-first delivery + heartbeat / TTL self-heal), replacing the old `SessionOwnerRegistry` point-to-point (`ip:port`) routing.

- `scripts/validate.mjs` + `.github/workflows/skill-lint.yml` — CI validation of frontmatter + References Index integrity.

### Changed
- `thinglinks-cloud`: downlink chain rewritten around **`DeviceDownlinkFacade`** (protocol-agnostic `dispatch(DownlinkCommand)`; boot = in-process / cloud = Feign `thinglinks-broker-server`) → `DeviceDownlinkDispatchService` → `MqttDownlinkSender` / `WebSocketDownlinkSender` / `TcpDownlinkSender`. Corrected a wrong premise: there was **no** old broker-api `@Component` downlink dispatcher — protocol branching used to be inlined in callers and is now centralized.
- `thinglinks-web`: documented the WS/MQTT debug pages' `IotProductPicker` + `IotDevicePicker` "按设备" usage and the `<a-radio-group :options option-type="button">` segmented-toggle convention.
- `thinglinks-cloud`: **references reorganized by application domain** into `references/{system,iot,video}/`; `SKILL.md` reframed from IoT-only to the full cloud platform (system foundation + IoT + video), trigger description broadened. `scripts/validate.mjs` now walks nested reference subdirs.
